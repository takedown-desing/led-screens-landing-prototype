# Вариант 5 · Истории объектов

Ответ на замечание Макса (07.10.2026): варианты 1–4 выглядят «сгенерированными ИИ» (лишние графические элементы, технические тексты с точкой после каждой фразы, плотная трудночитаемая информация), а первый экран должен показывать суть компании, а не описывать её.

Открывать через веб-сервер из папки `prototype/`: `python3 -m http.server 8796` → `http://localhost:8796/design/v5/`.

## Идея

Страница построена как рассказ, а не как набор секций.

1. **Витрина включается.** Первый экран: стеклянная стена шоурума, тёмная и бесцветная, подпись «Обычная стеклянная стена шоурума». При прокрутке ряды светодиодов зажигаются сверху вниз (36 рядов, на границе светится разогревающийся ряд), сквозь них проступает ролик, подпись меняется: «…пока в неё не встроили прозрачный LED-экран». Потом заголовок, кнопка «Хочу такую витрину» и телефон. Это главный продукт компании, показанный буквально. Два слоя и CSS-маска, без WebGL.
2. **Главы.** Каждый объект из «Объектов» — глава на весь экран: видео фоном, номер и тип, заголовок, два-три живых предложения, строка фактов, кнопка «Хочу так же» и цена типа экрана, к которому объект относится («такой экран от 85 000 ₽ за м²»). Типы растворены в историях.
3. **После глав коротко:** «Что ещё бывает» (шесть строк типов), калькулятор с фразой «в цену входит…», письмо от менеджера от первого лица вместо этапов и таблицы, абзац о компании, разговорные ответы на вопросы, «Написать Ивану».

Чего нет: иконок, бейджей, градиентов, карточек-плиток, бенто, цифр-барабанов, карусели, таблицы шага пикселя, отзывов-заглушек.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Каркас: шрифт Golos Text (Google Fonts), стили, скрипты, плашка варианта |
| `render.js` | Сборка страницы из `../../content/landing.json` |
| `app.js` | Интерактив: витрина, модалка, меню, калькулятор, FAQ, автовидео, цвет шапки по тону секции |
| `styles.css` | Стили. Бумага `#f6f4ee`, текст `#141414`, синий логотипа `#0066ff` на ссылках и кнопке шапки, зелёный `#19c37d` только для «включения» |

## Новые поля контента

Добавлены в `content/landing.json` и в админку с пометкой «вариант дизайна 5». Старые поля не менялись, варианты 1–4 и прототип их не читают.

| Поле | Где выводится | Если пусто |
|---|---|---|
| `hero.sceneOff`, `hero.sceneOn` | подписи первого экрана до и после включения | подписи не выводятся |
| `hero.titleShort` | заголовок первого экрана (общее с вариантом 4) | `hero.h1` |
| `cases.items[].story` | текст главы | `desc` |
| `process.letter` | письмо от менеджера, абзацы через пустую строку, подпись из контактов | этапы абзацами |
| `faq.items[].talk` | ответ в «Вопросах» | `a` |

Тексты в новых полях написаны по правилам: ни одной подписи с точкой в конце, без «под ключ», «качество», «индивидуальный подход», только факты из JSON, непроверенное в `[[…]]`.

## Как блоки используют данные

* Порядок блоков из `blocks`, но главы объектов всегда идут раньше списка типов.
* Видео первого экрана: объект с фильтром `transparent`, иначе `hero.video`.
* Цифры доверия (`trust`) одной строкой под первым экраном. «Что входит» (`included`) одной фразой под калькулятором. Таблица шага пикселя (`specs`) не выводится.
* Отзывы показываются только настоящие: если текст целиком в `[[…]]`, отзыв скрыт; без настоящих отзывов секции нет.
* Факты объекта со значением в `[[…]]` (например «город уточнить») в строке фактов не показываются.
* Заголовок контактов «Написать Ивану» склоняет имя из `settings.contactName` простым правилом; если имя не склоняется, выводится `contacts.title`.
* Кнопка «Включить звук» в главе включает звук у ролика главы.

## Известные ограничения

* При «уменьшить движение» витрина показана сразу включённой, обе подписи видны.
* Формы ничего не отправляют, после отправки показывают `settings.formDone`.
* Вертикальные ролики в главах показаны целиком на размытой подложке.
