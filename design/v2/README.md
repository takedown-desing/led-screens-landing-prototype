# Вариант 2 · Контраст

Дизайн-вариант лендинга в языке сайта «Цвета Города»: чёрные секции ритмом, светлые преобладают, акцент `#FF5900`, шрифт Manrope, ключевые слова заголовков оранжевым КАПСОМ, бегущая строка, вращающийся бейдж.

Открывать через веб-сервер из папки `prototype/`: `python3 -m http.server 8793` → `http://localhost:8793/design/v2/`.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Каркас: шрифт, стили, скрипты. Текстов нет |
| `render.js` | Сборка страницы из `../../content/landing.json` |
| `app.js` | Интерактив: модалка, меню, карусель объектов, лайтбокс, калькулятор, отзывы, появление при прокрутке |
| `styles.css` | Стили. Цвета в CSS-переменных, акцент `--accent` |

## Откуда берётся контент

Всё из `content/landing.json`, того же файла, что правит админка. Порядок и видимость блоков из `blocks`, меню из `blocks[].menu`. Скрытые блоки и элементы с `visible: false` не выводятся. `[[текст]]` выводится как обычный текст, `\n` превращается в перенос, пустая строка делит абзацы. Медиа-пути из JSON получают префикс `../../`, абсолютные URL остаются как есть.

## Оранжевое выделение в заголовках (ACCENT)

В начале `render.js` есть карта `ACCENT`: для каждого блока указана подстрока заголовка, которая выводится оранжевым жирным КАПСОМ.

```js
var ACCENT = { hero: 'под ключ', trust: 'своими бригадами', screens: 'светодиодных экранов', cases: 'объекты', ... };
```

Поиск без учёта регистра и разницы «е/ё». Если клиент поменял заголовок в админке и подстроки в нём больше нет, заголовок выводится целиком без выделения, ничего не ломается. Чтобы выделить другое слово, поменяйте строку в `ACCENT`. В H1 выделение, стоящее в конце заголовка, переносится на отдельную строку и увеличивается.

## Фон секций (THEME)

Карта `THEME` в `render.js` задаёт фон по id блока: `light`, `grey`, `dark`, `orange`. Ритм по умолчанию: hero чёрный → цифры белый → типы экранов серый → объекты чёрный → что входит белый → этапы серый → калькулятор чёрный → шаг пикселя белый → о компании серый → отзывы чёрный → заявка оранжевый → вопросы белый → контакты и подвал чёрные. Если в админке поменять порядок блоков, фон останется за блоком.

## Как блоки используют данные

* **Hero**: `hero.h1`, `lead`, видео `hero.video` с постером. Кнопка `hero.formButton` открывает модальную форму, `button1` ведёт к калькулятору. Текст вращающегося бейджа берётся из `button2`, печать «Москва и Московская область» из первой части `hero.badge` (до запятой). Подпись на видео берётся из объекта, у которого то же видео.
* **Бегущая строка**: первый ряд из `hero.facts[].title` и частей `hero.badge`, второй ряд из `included.items[].title`.
* **Цифры** (`trust`): плитки с оранжевыми числами. Справа заголовок из `hero.badge` и список `hero.facts` с галочками. Фото между плитками берётся из постера второго объекта.
* **Типы экранов**: на картинке пилюля с шагом пикселя `px`, служебное поле `chip` («Фото клиента») на странице не выводится. Кнопка «Примеры» появляется, если у типа задан `caseFilter` и есть объекты с таким фильтром.
* **Объекты**: карусель. На десктопе в кадре одна большая и две маленькие плитки, на планшете и телефоне одна плитка и край следующей. Автопрокрутка раз в 6 секунд. Она останавливается при наведении, при фокусе, при открытом окне, когда вкладка скрыта и когда включено «уменьшение движения». Видео видимых плиток играют без звука, остальные на паузе и не грузятся (`preload="none"`). Клик открывает лайтбокс со звуком и кнопкой «Хочу такой же экран».
* **Что входит**: первые четыре пункта идут большими карточками. Пункт про гарантию (иконка `shield` или слово «гарант» в названии) показан оранжевой карточкой с крупной цифрой: цифра берётся из первого `[[…]]` в тексте пункта. Остальные пункты собраны в список. Фото берётся из первого типа экрана, подпись под ним из `included.sub`.
* **Калькулятор**: типы с `rate > 0`. Площадь × ставка, монтаж добавляет `mountShare`%. Округление до тысяч. Ниже идут карточки «ставка за м²», клик по карточке выбирает тип в калькуляторе.
* **Контакты**: `contacts.mapNote` выводится как заглушка на месте будущей карты.

## Тексты, которые заданы в коде, а не в JSON

Это подписи элементов интерфейса и одна полоса-побуждение, в модели контента для них полей нет:

* «Хотите **такой же** экран? Покажем, как он будет смотреться на вашем фасаде» и кнопка «Покажите» под каруселью;
* «Хочу такой же экран» в лайтбоксе;
* «Ставка за м² по типам экранов», «Ориентировочная стоимость», «Тип экрана», подписи строк результата калькулятора;
* заголовки колонок таблицы шага пикселя;
* «Не нашли ответ?» в блоке вопросов;
* подписи полей форм, «Позвонить», «Разделы».

Если клиент захочет править их в админке, нужно добавить поля в `landing.json` и в админку.

## Известные ограничения

* Формы ничего не отправляют, после отправки показывают `settings.formDone`.
* Режим предпросмотра из админки (`?preview=1` и postMessage) в варианте не подключён, страница всегда читает сохранённый `landing.json`.
* Плашка «Вариант 2 · Контраст · все варианты →» ведёт на `../`, там должен быть `design/index.html`.
